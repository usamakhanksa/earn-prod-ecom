Build a production-ready SaaS web app called **ReplyRight**.

## What it does
Business owners paste in a customer review (and optionally their business name
and preferred tone) and get 3 ready-to-post reply drafts generated by the
Anthropic API. Free users get 5 generations/month; paid users get unlimited via
a $15/month Stripe subscription.

## Tech stack (use these, don't substitute without telling me why)
- Next.js (latest stable, App Router), TypeScript, Tailwind CSS
- Supabase for auth (email/password + magic link) and Postgres database
- Stripe for subscription billing (Checkout + Customer Portal + webhooks)
- Anthropic API for text generation — use model `claude-haiku-4-5-20251001`
  (cheapest current model, sufficient for this task)
- Deploy target: Vercel

## Core features to build
1. **Landing page** — clear headline, 3-step "how it works," pricing (Free vs
   $15/mo Pro), and a live demo box where a visitor can generate ONE sample
   reply without signing up (rate-limit this by IP to prevent abuse).
2. **Auth** — Supabase email/password + magic link. Redirect new users to
   onboarding, existing users to dashboard.
3. **Dashboard** — a form: paste review text, optional business name, tone
   selector (Professional / Friendly / Apologetic). On submit, call the
   Anthropic API and return 3 distinct reply drafts the user can copy with one
   click. Show remaining free generations for free-tier users.
4. **Usage limits** — track generations per user per calendar month in
   Postgres. Free tier: 5/month, hard stop with an upgrade prompt after that.
   Pro tier: unlimited.
5. **Billing** — Stripe Checkout for upgrading to Pro, a webhook endpoint that
   updates the user's plan in Postgres on `checkout.session.completed` and
   `customer.subscription.deleted`, and a "Manage billing" link to the Stripe
   Customer Portal.
6. **Account page** — show current plan, usage this month, and billing
   management link.

## Database schema (Supabase/Postgres)
- `profiles`: id (uuid, FK to auth.users), email, plan ('free' | 'pro'),
  stripe_customer_id, stripe_subscription_id, created_at
- `generations`: id, user_id (FK), review_text, created_at — used to count
  monthly usage (count rows in current calendar month, don't add a separate
  counter column that can drift out of sync)

## Non-negotiable requirements
- Never expose `SUPABASE_SERVICE_ROLE_KEY` or `STRIPE_SECRET_KEY` to the
  client — server-side only (API routes / server actions).
- Enforce the free-tier limit server-side, not just in the UI (a user editing
  browser state should not bypass it).
- Handle Anthropic API errors gracefully — show the user a retry message, don't
  crash the page or silently fail.
- Verify Stripe webhook signatures before trusting webhook payloads.
- Write the code so it runs locally with `npm run dev` using a local `.env.local`,
  and deploys cleanly to Vercel with the same env vars set in the dashboard.
