## Status: IMPLEMENTED (backend + web + mobile; live-infra paths honestly stubbed/gated — see
"Still stubbed" below)

Exit criteria from implentationplanphase.md: *"user uploads a design, passes preflight, builds a
product with a 24-variant matrix, applies a pricing rule, and sees a correct live margin

## Bugs found and fixed while getting this pass green

Every one of these was caught by writing real tests against real code, not review alone:

- **`money-math.ts` `scaleMinor`**: `100n * 1.005` evaluates to `100.49999999999999` in IEEE-754
  double precision, so a naive round would silently round a "nice" decimal factor the wrong way
  (101 vs 100). Fixed with a relative epsilon nudge before rounding — the standard technique for
  decimal-looking float factors, safe at any realistic money magnitude.
- **`money-math.ts` `roundPsychological99`**: the first implementation used a plain ceiling-
  division formula that mapped an exact `$12.00` down to `$11.99` instead of up to `$12.99` —
  backwards from how psychological pricing is actually applied (never undercut a computed price).
  Derived and fixed the correct "smallest N.99 ≥ input" formula; added an idempotence test
  (`$12.99` → `$12.99`) to lock in the corrected behaviour.
- **`csv.util.ts`**: the first `csvToProductRows` implementation split the input on `\n` *before*
  parsing quoted fields, so a quoted field containing an embedded newline got cut into two rows —
  a real CSV-correctness bug. Rewrote as a single quote-aware pass over the whole text that only
  terminates a row on an *unquoted* newline.
- **`packages/ui` dual-React-copy hazard (new, same family as `docs/DEBT.md` 1-D15/1-D16)**:
  `packages/ui` pins its own `react@19.0.0`, but `react-dom` (used by its test suite's
  `renderToString`) resolves to the workspace root's `react@18.3.1` (pulled in by
  `apps/mobile`'s React Native 0.76). The first `MarginWaterfallChart` implementation used
  `useState`/`useEffect` to drive a mount-triggered grow animation and detect
  `prefers-reduced-motion`; every render threw `Invalid hook call` in this package's test file
  (the package's *first* hook-using component — Button/Badge/Skeleton/Spinner have none, so this
  was never exposed before). Rewrote the component hook-free: a pure CSS `scaleY` keyframe handles
  the grow-in animation, and a plain `@media (prefers-reduced-motion: reduce)` override disables
  it — a genuinely better implementation for this component, not just a workaround, and it let the
  real render tests pass. Recorded as `docs/DEBT.md` 2-D13 since the underlying dependency-graph
  hazard is still open for any *future* hook-using component in that package.
- **Zero-byte chunk validation**: `uploadChunkSchema.chunkBase64` originally required `min(1)`,
  which would reject the one legitimate zero-length chunk case (an empty file's only "chunk").
  Relaxed to allow an empty string — the server's real safety net is the offset check, not a
  minimum chunk size.
- **My own verification mistake, not a code bug**: running `next dev apps/web -p 3010` from the
  repo root (positional directory argument) broke Tailwind's config resolution and made *every*
  route 500 — including pre-existing, untouched pages. Not a regression; re-running via
  `pnpm --filter @omnisell/web dev` (matching Phase 1's own invocation) resolved it immediately and
  confirmed all new routes return 200. Noting this so a future pass doesn't waste time
  re-diagnosing the same non-bug.
